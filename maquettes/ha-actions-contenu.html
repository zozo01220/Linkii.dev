Home Assistant : piloter le contenu des écrans

Aujourd'hui Home Assistant sait allumer, éteindre et redémarrer un écran. Il ne sait pas encore lui dire quoi afficher. Cette maquette ajoute des actions Home Assistant : les automatisations de l'utilisateur (sonnette, fumée, présence…) appellent Linkivi, qui affiche un message, une liste ou une alerte d'urgence, puis revient à la diffusion normale. Les règles se font donc dans l'éditeur d'automatisations de Home Assistant, avec ses conditions et ses modèles : rien à reconstruire dans Linkivi.

1 · Les actions, vues dans l'éditeur d'automatisation de Home Assistant

Quatre actions fournies par l'intégration. Les écrans se choisissent comme n'importe quel appareil Home Assistant : un écran, une pièce (« aire » de Home Assistant, qui regroupe déjà ses appareils) ou tout.

2 · Des automatisations types, en YAML

Ce que l'utilisateur écrit (ou ce que l'éditeur visuel produit). Des modèles d'automatisation (blueprints) seraient fournis avec l'intégration : on choisit le capteur et les écrans, sans écrire de YAML.

# Sonnette → message 30 s à l'accueil, de jour seulement
trigger: - platform: state, entity_id: binary_sensor.sonnette, to: "on"
condition: - condition: time, after: "07:00:00", before: "19:00:00"
action:
  - action: linkivi.show_message
    target: { area_id: accueil }
    data: { title: "Un visiteur est à l'accueil", message: "Merci d'aller l'accueillir", duration: 30 }

# Détecteur de fumée → urgence, levée quand le détecteur revient à la normale
trigger: - platform: state, entity_id: binary_sensor.fumee_etage_1, to: "on"
action:
  - action: linkivi.start_emergency
    data: { title: "Évacuation", message: "Rejoignez le point de rassemblement", all_screens: true }
  - wait_for_trigger: [ { platform: state, entity_id: binary_sensor.fumee_etage_1, to: "off" } ]
  - action: linkivi.end_emergency

3 · Sur les écrans et dans Linkivi

La diffusion en cours n'est pas perdue : elle reprend là où elle s'était arrêtée. L'urgence garde ses règles actuelles et passe devant tout le reste.

4 · Ce qui existe déjà, ce qu'il faut ajouter

BriqueAlerte d'urgenceMessage / liste
API LinkiviExiste déjà : POST /emergency et DELETE /emergency/{id} (module Urgence, accès emergency:write).À créer : POST /screens/{id}/display (message ou liste, durée) et DELETE pour arrêter ; lecture des listes de lecture pour le choix dans Home Assistant.
PlayerExiste déjà (plein écran rouge, réveil).Un nouveau « affichage temporaire » : un contenu qui passe devant la diffusion pendant N secondes, puis rend la main. Commun au message et à la liste.
Intégration Home AssistantQuatre actions + le capteur « Urgence en cours » + des modèles d'automatisation. La carte « Écrans Linkivi » pourra plus tard recevoir un bouton « Envoyer un message ».
